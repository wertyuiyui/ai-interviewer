# 模拟面试阶段流设计依据

## 结论

公开面经呈现的共同结构不是“每类题固定问几轮”，而是相对稳定的阶段顺序与阶段内动态追问：技术面通常从自我介绍进入项目深挖，再覆盖基础/场景题、手撕代码和候选人反问；技术综合面在此基础上增加行为与动机问题；独立综合面聚焦经历、选择、协作、动机和反问，不应混入八股或手撕代码。

面经只代表具体候选人、岗位、部门和时间点，不是公司的官方固定流程。产品据此提炼交互原则，而不复刻单篇面经的题目顺序。

## 公开样本

- [字节跳动后端实习面经](https://www.nowcoder.com/discuss/831675)：项目会被连续深挖，随后进入基础题与较长的代码题；候选人卡住时，面试官可能给提示并观察思路。
- [后端技术面与 HR 面流程复盘](https://www.nowcoder.com/discuss/441726063497003008)：技术面出现自我介绍、项目、MySQL 等基础题、算法与反问；HR 面则以自我介绍、实习/校园经历和反问为主。
- [阿里后端项目深挖复盘](https://www.nowcoder.com/discuss/470248886167216128)：项目细节与基础原理会交叉追问，追问方向取决于候选人回答中暴露的技术点。
- [美团面试流程复盘](https://ac.nowcoder.com/discuss/507668)：实习/项目深挖后覆盖基础知识、职业选择、算法和反问。
- [综合面问题复盘](https://www.nowcoder.com/discuss/735252226783920128)：综合面主要考察经历、动机、自我认知和工作场景。
- [技术面自适应跳题样本](https://www.nowcoder.com/discuss/661915101359878144)：真实流程会根据现场表现调整原定基础题覆盖，而不是机械走完模板。

## 产品阶段

| 面试类型 | 阶段顺序 |
|---|---|
| 技术面 | 自我介绍 → 项目深挖 → 基础与场景题 → 手撕代码 → 反问 |
| 技术 / 综合面 | 自我介绍 → 项目深挖 → 基础与场景题 → 手撕代码 → 综合交流 → 反问 |
| 综合面 | 自我介绍 → 综合交流 → 反问 |

阶段由服务端持久化并作为唯一事实源。前端只渲染服务端返回的当前、已完成、已跳过和待进行状态；重连后不得用本地轮次重新推算。

## 自适应规则

1. 先识别回答意图和有效信息，再决定深挖、换题或换阶段。模型生成的追问必须同时锚定当前主题和候选人刚说出的具体信息。
2. 项目阶段不强制走固定话术层级。回答出现新事实时追问事实；含糊回答最多澄清一次；明确表示项目不属于本人时按归属纠正处理。
3. 明确说“我不知道”或点击同名按钮时，结束当前问题上下文。若正在项目深挖，直接离开该项目阶段并清空项目锚点；在基础或综合阶段则跳到另一个主题，不重复当前主问或其追问。
4. “直接进入下一阶段”是控制事件，不是候选人回答，不生成虚假 turn，也不参与评分。服务端用阶段 revision 防止重复点击和乱序请求。
5. 基础和综合阶段采用“审核主问 + 至多一次回答锚定追问”的结构；追问不是固定改写模板，生成结果不满足双重锚定时才使用安全回退。
6. 综合面计划从源头排除项目技术下钻、八股和手撕代码，而不是依靠前端隐藏。

## 最小验收

- 技术面、技术综合面、综合面返回不同且稳定的阶段计划。
- 项目阶段点击“不知道”后进入非项目阶段，下一问不包含旧项目名，持久化 anchor 为空。
- 跳阶段后 turn 数不变，刷新/重连仍处于新阶段；旧 revision 被拒绝。
- 进度条和下一阶段按钮使用服务端快照；语音和文字回答完成事件都携带同一快照。
- 项目正常回答时，下一问优先使用回答中的事实；不合格生成结果才回退到安全项目问题。
